# NanoDesk App 使用手冊

NanoDesk App 是 Windows 原生遠端桌面程式。同一個 `NanoDesk-App.exe` 可控制其他電腦，也可接受控制。App 與 ID／中繼伺服器使用協定版本 2，請一起更新。伺服器部署請參考 [伺服器使用手冊](../server/README.md)。

## 1. 首次啟動

App 有一般版與預設連線版兩種模式。伺服器匯出的預設連線版已內建並鎖定網址與公開 CA，開啟後會直接嘗試上線，可略過下列網址與 CA 設定步驟。連線模式、密碼、剪貼簿等其他偏好仍可修改。

內嵌網址與 CA 優先於這台電腦原有設定，且只於執行時套用。儲存其他偏好或自動儲存裝置 ID 時，不會覆寫原有網址與 CA；改用一般版後仍會讀取原值。兩種模式共用本機裝置身分。每台新電腦首次開啟時自行產生身分，匯出檔不含裝置私鑰或登入密碼。

1. 在控制端與被控端都開啟 `NanoDesk-App.exe`。
2. 點右上角齒輪，進入「連線與伺服器」。
3. 填入伺服器的 HTTPS 網址，例如 `https://desk.example.com`。使用非 443 埠時填入 `https://desk.example.com:8443`。
4. 若伺服器使用自簽憑證，先把伺服器匯出的公開 CA 檔案複製到這台電腦，再於額外 CA 欄位指定該檔案。公開受信任憑證可留空。
5. 先選「自動：直連優先，中繼備援」，儲存設定。
6. 等待狀態顯示上線，主頁會出現本機的十位固定 ID。兩端須連到同一台 ID 伺服器。

網址只填主機與連接埠，格式為 `https://主機名稱:連接埠`。額外路徑、帳密與查詢字串不受支援。憑證須符合這個主機名稱或 IP。

`127.0.0.1` 指向正在執行 App 的電腦。伺服器在另一台電腦時，請填伺服器可達的區網 IP、VPN IP、公網 IP 或網域。

### 連線模式

| 模式 | 使用方式 |
| --- | --- |
| 自動：直連優先，中繼備援 | 提供直連及中繼候選，由 ICE 選路。中繼容量不足時仍可嘗試直連。 |
| 強制中繼 | 透過伺服器中繼，適合確認中繼設定。UDP 探測失敗時可選 TLS 路徑。 |
| 僅 TLS 中繼 | 跳過 UDP 探測，經伺服器 HTTPS 的獨立資料連線傳輸。適合 UDP 不可用的環境。 |

TLS 中繼與協調服務共用 HTTPS 入口。App 仍會驗證憑證與主機名稱。網路設備或代理也可能限制長時間 WebSocket 連線。

## 2. 連到對方電腦

1. 從被控端取得十位 ID。
2. 在控制端的「新增連線」分頁輸入對方 ID。
3. 選擇請求授權，或輸入對方已設定的角色密碼。
4. 使用人工授權時，被控端需在請求視窗選擇授權角色。
5. 授權成功後顯示遠端畫面。要操作鍵鼠時，可從「主控權」選單取得／接管主控權。
6. 關閉遠端分頁即可結束該連線。

授權成功前不傳送桌面畫面。對方 App 必須持續執行，Windows 使用者也須處於可操作的互動桌面。

### 角色與主控權

| 角色 | 主要權限 |
| --- | --- |
| 僅觀看 | 查看畫面，不能注入鍵鼠、同步剪貼簿或傳送檔案。 |
| 一般控制 | 可操作一般鍵鼠、同步剪貼簿及傳送檔案，部分特權快捷鍵受限制。 |
| 完全控制 | 可使用 App 提供的完整控制功能，仍受 Windows 桌面與權限限制。 |

多人可同時連到同一台被控電腦，鍵鼠操作由目前的主控者執行。「主控權」選單可取得／接管或釋放控制權。被控端有人在本機操作時，遠端輸入可能暫時被抑制。

這些角色是 NanoDesk 的應用程式權限，不能取代 Windows 的使用者權限。

### 無人值守

在被控端的「安全與授權」啟用無人值守，並至少設定一種角色密碼。未填密碼的角色不能使用密碼登入。無人值守預設關閉，啟用後 App 仍須保持執行。

## 3. 同時控制多台主機

建立一條連線後，可回到「新增連線」連到下一台主機。每條連線有獨立分頁，可以拖曳排序、拖出主視窗成為獨立視窗，或拖回頂部分頁列。獨立視窗也提供「移回主視窗」。移動分頁會保留連線。

每個 App 最多維持 16 條連入與連出工作階段，兩者合計。鍵鼠送到目前操作的遠端視窗，各被控主機分別管理自己的授權與主控者。

## 4. 遠端工具列

把滑鼠停在圖示上可查看名稱與狀態，部分圖示點擊後會開啟選單。

| 功能 | 操作 |
| --- | --- |
| 縮放與全螢幕 | 調整畫面比例或切換全螢幕。 |
| 主控權 | 取得／接管或釋放鍵鼠控制。 |
| 快捷鍵 | 傳送 Windows 鍵、Alt+Tab、顯示桌面等支援的操作。 |
| 剪貼簿 | 開啟／關閉自動同步，或使用貼上入口。 |
| 檔案傳輸 | 選檔傳送，或取消目前傳輸。 |
| 對話 | 與該工作階段的對方交換訊息。 |
| 編號螢幕 | 切換被控端螢幕，提示會顯示解析度及主要螢幕。 |

切換被控端螢幕需符合主控權規則，並會影響同一被控桌面的其他觀看者。失焦或斷線時會釋放按鍵。指示筆可用於協同觀看。

被控端另有連入工作階段小窗，可依來源裝置查看角色、主控狀態、傳送對話或結束連線。對話保存在當次工作階段的記憶體中。

新授權連入時，小窗會短暫置頂提醒約兩秒，之後可被其他視窗覆蓋；切換焦點或最小化也會提前解除置頂。小窗可從工作列還原，最小化不會中斷連線，主控權、角色或聊天更新不會把它重新彈出。新的連入工作階段仍會提醒一次；關閉小窗則會先詢問是否結束連入工作階段。

## 5. 雙向剪貼簿

在遠端工具列的「剪貼簿」選單啟用自動同步。一般控制及完全控制的連線可以同步，僅觀看者不會收到剪貼簿內容。剪貼簿權限與鍵鼠主控權分開。

### 文字、富文字與圖片

1. 在來源端用原程式的複製功能或 `Ctrl+C` 複製。
2. 切到另一端的目標程式。
3. 使用 `Ctrl+V` 或該程式的貼上功能。

同步格式包含 Unicode 純文字、HTML、RTF、PNG／DIB 圖片。同一次複製可包含多種格式，由目的程式選擇支援的格式。應用程式私有格式需另行驗證。

### 檔案與資料夾

**本機貼到遠端**

1. 在本機檔案總管複製檔案或資料夾。
2. 切到要操作的遠端分頁。
3. 在遠端開啟目標資料夾，或將焦點放到支援貼檔的程式。
4. 按 `Ctrl+V`，或使用目標程式的貼上功能。

**遠端貼回本機**

1. 在遠端檔案總管複製檔案或資料夾。
2. 切回本機的目標資料夾或支援貼檔的程式。
3. 使用本機程式的貼上功能。

複製時同步檔案清單，目標程式讀取內容時才傳輸。檔案會交給目標程式處理，因此檔案總管可貼到目前資料夾，其他程式則依自己的功能處理。

貼檔使用 Windows OLE 虛擬檔案格式。檔案總管與支援該格式的程式可讀取內容，只接受實體檔案路徑的程式可能無法貼上。工具列目前仍顯示「貼上本機文字／圖片」，檔案日常操作請使用目標程式的貼上功能。

剪貼簿檔案採複製語意。檔案總量受設定的傳輸上限限制，單次清單最多 4,096 個檔案／資料夾項目；過長相對路徑、連結或來源變更可能使讀取失敗。

### 多人同步規則

同一被控桌面的所有已啟用同步、且具有一般控制以上權限的連線共用剪貼簿。最後一次複製會取代前一次。A 複製後若 B 又複製其他內容，A 隨後貼上 B 的新內容是正常行為。

剪貼簿沒有固定的貼上倒數。切換視窗或交接鍵鼠主控權不會讓內容自行過期。新複製、來源檔案變更、來源離線、連線結束或停用同步會影響後續檔案讀取。

同時連到多台主機時，本機仍只有一份 Windows 剪貼簿。接收更新會改變本機可貼上的內容；本機新複製則由目前操作的遠端分頁發送。

## 6. 工具列檔案傳送

工具列的「檔案傳輸 → 傳送檔案」會把選定檔案存到被控端的實際桌面。要自行指定資料夾時，可使用上一節的剪貼簿貼檔。

每批最多 100 個檔案，預設總內容上限為 1 GiB，可在「剪貼簿與檔案」調整。相同檔名會加序號。使用小區塊可靠傳輸與約 1 MiB/s 節流，進度會區分傳送及等待主機儲存。

「取消傳輸」位於同一選單。30 秒無進度、取消、斷線或撤權會清理未完成接收檔案，已完成檔案保留。僅觀看者不能傳檔。

## 7. 連線中斷與恢復

中繼路徑每秒心跳，約三秒沒有有效回應時會申請新路徑。恢復時畫面可能短暫停頓，可靠資料會嘗試續傳；十五秒內仍無法恢復則結束工作階段。進行中的檔案／貼上若顯示失敗，請在連線恢復後重新發起。

影像會依中繼頻寬預算與 RTCP 丟包回報調降目標碼率，網路持續恢復後才逐步提高；畫面過大時會先降低擷取頻率。接收端限制舊影像封包的重試次數，缺包後等待完整關鍵幀，避免持續使用破損的相依畫面。同一被控桌面共用編碼，採用已授權觀看者中較低的頻寬預算。這些措施不能消除持續斷網或壅塞造成的停頓。

關閉 App、變更伺服器設定或協調連線中斷，仍可能使整個工作階段結束。儲存 App 設定會撤銷既有授權並中斷連線，單純開啟或切換設定分頁不會中斷。

## 8. 固定 ID 與備份

首次啟動建立 Ed25519 金鑰，由伺服器分配十位 ID。身分與設定以 Windows DPAPI 加密，位於 `%LOCALAPPDATA%\NanoDesk\state.bin`。

同一 Windows 使用者與電腦上更新或移動 EXE 會沿用身分。不同使用者、重灌、遺失身分或更換伺服器可能取得不同 ID。請保留伺服器的 ID 資料庫；不要把同一份 App 身分檔複製到另一台電腦使用。損壞或無法解密的狀態不會自動覆寫。

## 9. 疑難排解

| 現象 | 先檢查 |
| --- | --- |
| 無法上線 | 伺服器已啟動、HTTPS 網址與埠正確、兩端版本一致。 |
| 憑證或主機名稱錯誤 | 網址符合憑證，額外 CA 是本機存在的公開 CA 檔案。 |
| 對方不在線上 | 對方 App 持續執行，兩端使用同一台 ID 伺服器。 |
| 看得到但不能操作 | 授權角色、主控權與被控端本機操作狀態。 |
| 剪貼簿未同步 | 同步開關、角色、目前操作的分頁，以及是否被另一人新複製覆蓋。 |
| 某程式不能貼檔 | 先試檔案總管，確認目標程式支援 OLE 虛擬檔案，來源與連線仍有效。 |
| 中繼無法建立 | 伺服器端點池容量、公布位址、UDP 轉送與 HTTPS 連線。可選僅 TLS 模式定位問題。 |
| 黑畫面或畫面停滯 | 被控端為已登入且可操作的互動桌面，顯示驅動及 Media Foundation 正常。 |

## 10. 支援範圍與驗證狀態

Windows 10／11 x64，需 Media Foundation 與 Direct3D 11。App 與 Web 各自連線。音訊、錄影、Windows 開機服務、登入畫面、UAC 安全桌面及真正 Ctrl+Alt+Del 尚未提供。

本機已驗證共用 Port 的二十組混合工作階段、UDP／TLS 中繼與路徑恢復。跨實體電腦、多網卡及 NAT 的驗收依目前決定暫緩；完整結果與既有測試失敗見 [驗證紀錄](../TESTING.md)。執行檔大小與 SHA256 見 [BUILD-SIZES.txt](../BUILD-SIZES.txt)。
