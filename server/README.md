# NanoDesk 伺服器使用手冊

`NanoDesk-Server.exe` 提供固定 ID 登錄、連線協調與 UDP／HTTPS TLS 中繼。它與原生 App 使用協定版本 2，請一起更新。控制端及被控端的操作見 [App 使用手冊](../app/README.md)。

## 匯出免設定 App

將新版 `NanoDesk-App.exe` 與 `NanoDesk-Server.exe` 放在同一資料夾。完成並儲存伺服器設定後，在主控台按「匯出預設連線 APP…」，另存為 `NanoDesk-App-Configured.exe`，即可將單一 EXE 交給使用者。

匯出只內嵌已儲存的 HTTPS 網址與公開 CA，不含伺服器私鑰、裝置身分或密碼。原始 App 範本保持不變；匯出時不需 Go 或編譯工具。網址或憑證更換後須重新匯出並分發 App。若範本有數位簽章，請改用未簽章範本，匯出後再簽章。

預設連線版鎖定網址與 CA，其他設定照常編輯。內嵌值不會寫回並覆蓋本機原有的網址與 CA。

## 1. 先決定部署位址

先找出 App 實際能連到的伺服器位址，再建立相符的憑證。下表為示意，請替換成自己的位址。

| 部署方式 | App 連線網址 | 端點綁定本機 IP | 端點公布位址 |
| --- | --- | --- | --- |
| 同一台電腦測試 | `https://127.0.0.1` | `127.0.0.1` | `127.0.0.1` |
| 同一區網 | `https://192.168.1.10` | `192.168.1.10` | `192.168.1.10` |
| 已互通的 VPN | 伺服器可達的 VPN IP／網域 | 伺服器的 VPN IP | App 可達的 VPN IP／網域 |
| 路由器後方的外網服務 | `https://desk.example.com` | 例如 `192.168.1.10` | 公網 IP 或 `desk.example.com` |

`127.0.0.1` 永遠指向使用該位址的本機。其他電腦連線時，不能把伺服器的 `https://127.0.0.1` 當成它們的連線網址。

綁定 IP 必須存在於伺服器的網卡上。公布位址則是 App 實際連往的目的地，兩者在 NAT 環境下可以不同。多網卡的 Windows 路由由管理者設定。

## 2. 第一次使用

1. 雙擊 `NanoDesk-Server.exe`，點右上角「設定」。
2. 在「一般連線」填入伺服器的 IPv4 或網域／DDNS，至少一項。網域只填主機名稱，例如 `desk.example.com`。
3. 在「憑證與 ID 資料」選擇 TLS 憑證、私鑰與 ID 資料庫位置。沒有憑證時可使用「建立自簽憑證」。
4. 在「進階連接埠」確認 HTTPS 監聽 IP 與 TCP 埠，通常使用 443。
5. 在「中繼端點池」勾選「啟用共用埠中繼池」，新增端點組及端點，填好下節列出的欄位。
6. 向下捲動，確認 UDP 埠、「此組為預設端點組」及「啟用此端點」。只能有一個預設組。
7. 按「儲存並啟動」。主控台應顯示服務運作中，並列出 App 連線網址。
8. 在控制端與被控端 App 填入這個網址。使用自簽憑證時，兩端也要取得並指定公開 CA 檔。

設定頁較長時，請在右側內容區使用滑鼠滾輪或捲軸查看下方欄位。UDP 埠、預設組、端點啟用與即時負載都位於端點池頁面的下半部。

僅開啟或切換設定分頁不會中斷服務。關閉未儲存的設定時，可以選擇儲存、捨棄或取消。

### 憑證與公開 CA

憑證必須符合 App 使用的主機名稱或 IP。更改連線位址後，請確認既有憑證仍包含該名稱。

「建立自簽憑證」會建立伺服器憑證、伺服器私鑰及公開 CA 檔案，並填入路徑。新檔不覆寫既有憑證。伺服器憑證有效一年，CA 簽章私鑰不保存。

按「匯出 CA 憑證」，把公開 CA 檔案帶到每台 App 電腦，再指定該電腦上的檔案路徑。複製伺服器的路徑文字並不能代替複製檔案。TLS 私鑰留在伺服器。

使用公開受信任憑證時，App 額外 CA 可留空。重新建立自簽憑證後，App 也需更新信任的公開 CA。

## 3. 中繼端點池欄位

每個 UDP Port 都可承載多個工作階段。設定五個 Port 不代表只能接受五條連線，實際接納數量受容量預留及協調層上限影響。

| 欄位 | 用途與填法 |
| --- | --- |
| 啟用共用埠中繼池 | 使用新的 UDP／HTTPS TLS 中繼。 |
| 總容量 Mbit/s | 伺服器中繼的總容量上限。 |
| 每端容量預留 Mbit/s | 每個工作階段端點接納時預留的容量，也是該端的速率限制依據。 |
| 端點組名稱 | 方便管理者識別用途，例如「內網」或「外網」。 |
| 來源 CIDR（逗號分隔） | 依伺服器看到的 App 來源 IP 選組，例如 `192.168.1.0/24,10.10.0.0/16`。 |
| 端點組容量 Mbit/s | 該組可預留的總容量。 |
| 綁定本機 IPv4／IPv6 | 伺服器實際監聽的網卡 IP，需填具體位址。 |
| 公布 IP／主機名稱 | App 可達的位址，不含 `https://`、路徑或 Port。 |
| UDP 埠（清單或範圍） | 例如 `3478`、`3478,3480` 或 `3478-3482`，每個端點最多 128 個埠。 |
| 此組為預設端點組 | 未符合任何來源 CIDR 時使用此組，整份設定需恰好一個預設組。 |
| 啟用此端點 | 控制該端點是否接受新配置。 |

來源符合多條 CIDR 時採最長前綴。例如 `10.1.0.0/16` 會優先於 `10.0.0.0/8`。來源是伺服器實際看見的 IP，經 NAT 的 App 通常會以外部來源位址比對。

同一組內可有多個端點，分別綁定不同網卡或不同 IP。同一個本機 IP／UDP Port 不能重複設定。App 探測候選端點後，伺服器依最近五秒流量、封包率、佇列壓力與預留數選擇，兩端可以使用不同端點及不同 IP 家族。

### 新增與編輯

- 「新增端點組」會建立一組及第一個端點。
- 選取清單內的端點後，下方顯示該端點與所屬組的欄位。
- 「新增組內端點」會加入目前所選的組，共用組名稱、來源規則及組容量。
- 修改組層級欄位會影響整組，修改綁定 IP、公布位址、UDP 埠及啟用狀態則影響所選端點。
- 移除組內最後一個端點會移除該組。儲存前仍需保留唯一的預設組。

### 單網卡的起始範例

假設兩端與伺服器都在同一區網，伺服器 IP 為 `192.168.1.10`。

1. App 網址使用 `https://192.168.1.10`，憑證也需包含這個 IP。
2. 新增一個預設組，來源 CIDR 留空。
3. 端點綁定及公布位址都填 `192.168.1.10`。
4. UDP 埠先填 `3478`，勾選啟用端點。
5. 容量依可用線路設定，例如總容量及組容量各 100 Mbit/s，每端預留 5 Mbit/s。
6. 儲存並啟動，再讓兩端 App 上線。

每個工作階段有兩端，各預留一份容量。兩端同組時，5 Mbit/s 的每端預留會讓該組每工作階段計入 10 Mbit/s。這是接納計算，不能單憑 Port 數推算連線上限。

### 多網卡及外網部署

新增多個端點，分別填入每張網卡的本機 IP。網卡共用同一條外網線路時，增加網卡或 Port 不會增加該線路的頻寬。多 Port 的用途包括分散 socket 處理與佇列負載，實際效益見 [本機量測紀錄](../TESTING.md)。

伺服器在路由器後方時，需要讓 HTTPS TCP 埠及公布的 UDP 埠到達相應本機 IP。外部與本機使用相同 UDP Port 號。

| 入站用途 | 需開放／轉送的埠 |
| --- | --- |
| ID 協調與 TLS 中繼 | 設定的 HTTPS TCP 埠，通常是 443。 |
| UDP 中繼及 STUN 映射 | 已啟用端點的 UDP Port 清單。 |

啟用新端點池後，舊 TURN UDP、TURN TLS 與動態中繼範圍不參與新池傳輸。「進階連接埠」畫面仍保留舊欄位，新池部署以 HTTPS 欄位和端點池的 UDP 清單為準。

`/signal` 與 `/relay` 需直接抵達此服務。目前不信任代理提供的來源 IP 標頭，會改寫來源 IP 的反向代理需另行驗證。

## 4. 日常管理

### 主控台

主控台提供服務狀態、App 網址、在線裝置、工作階段、中繼配置與紀錄。中繼配置以端為單位計數，一條工作階段可能計入兩個端。

「啟動服務」使用已儲存設定，「停止服務」會結束現有連線並釋放資源。關閉伺服器程式也會停止服務。

「開啟程式時自動啟動服務」會讓下次雙擊程式時使用已儲存設定。Windows 開機服務安裝與開機啟動需另行安排，目前程式沒有提供服務安裝器。

### 運行中修改端點池

已啟用端點池時，可在服務運作中修改端點、公布位址、來源規則及容量，按「儲存設定」套用。

新增 socket 與設定儲存全部成功後才切換設定。若 Port 已占用、綁定 IP 不存在或無法寫入設定，保留原本運行設定。改動 HTTPS 入口、憑證及資料庫需先停止服務；首次啟用或移除整個端點池目前也需先停止。

| 操作 | 既有工作階段 |
| --- | --- |
| 新增端點 | 既有連線保持原路徑，新配置可使用新增端點。 |
| 移除端點或取消啟用後儲存 | 停止接受新配置，既有連線排空後關閉 socket。 |
| 立即停用 | 先儲存停用狀態，再撤銷相關 UDP／TLS 路徑，App 嘗試改派。 |
| 降低容量 | 保留既有預留，直到容量回到新門檻以下再接受新配置。 |

「立即停用」需先儲存其他編輯。若沒有可用替代端點，連線可能無法恢復。

### 負載指標

向下捲動端點池頁面可查看每個 socket 的預留數、流量、封包率、佇列、丟包、改派路徑數及排空狀態。流量是最近五秒的平均，預留數與即時流量各有用途，空閒連線仍可能保有容量預留。

中繼使用有界佇列、通道輪替排程與速率限制。容量滿時會拒絕新中繼配置；App 預設模式仍可嘗試直連，強制中繼模式會回報失敗。

## 5. 故障恢復

App 每秒檢查中繼路徑，約三秒沒有有效回應時向仍在線的協調連線申請新路徑。新路徑更換金鑰與世代，保留原本 WebRTC 工作階段。

恢復期間畫面可能短暫停頓，可靠資料由 SCTP 重傳。十五秒內仍無法恢復時會結束工作階段，未完成接收資料會清理，已完成檔案保留。整個伺服器停止或協調連線失效，仍可能需要使用者重新連線。

剪貼簿授權與這個故障恢復期限分開。剪貼簿沒有貼上倒數，鍵鼠主控權交接也不會使已同步內容自行過期。

## 6. 設定、備份及版本更新

設定位於 `%LOCALAPPDATA%\NanoDesk-Server\server-settings.json`，其中保存設定值及檔案路徑。相對路徑以設定檔資料夾為準。

ID 資料庫保存 ID／公鑰對應。若 EXE 旁已有 `nanodesk.db`，首次設定可能沿用它。請確認資料庫路徑，更新 EXE 時保留既有資料庫，以維持 ID 對應。

### 備份與還原

1. 在主控台按「備份 ID 資料庫…」，選擇備份目的地。
2. 服務運作中會使用一致快照，目的地不能覆蓋正在使用的資料庫。
3. 另行保留設定檔、伺服器憑證及私鑰，資料庫備份不會包含這些檔案。
4. 還原時先停止服務，保留目前資料庫備份，再替換資料庫或選取備份檔路徑。
5. 重新啟動後，使用原 App 身分確認 ID 與連線正常。

### 舊設定遷移

載入舊設定會先保存原始內容到 `.pre-relay-v2.bak`，再產生待確認的端點池草案並關閉自動啟動。

提議的綁定 IP 與公布位址可能不適合實際網路，請逐項核對，尤其是 `127.0.0.1`。容量會參考舊頻寬設定，也需重新確認。確認後按「儲存設定」或「儲存並啟動」。若既有備份與待備份內容不同，遷移會停止並顯示錯誤。

App 與伺服器需同時更新至協定版本 2，舊 App 無法完成新版握手。更新後仍應保留既有身分及資料庫。

## 7. 選用命令列

日常操作可使用 GUI。使用 GUI 儲存的設定檔啟動時，執行下列命令。

```powershell
.\NanoDesk-Server.exe -cli -config "D:\NanoDesk\server-settings.json"
```

離線備份資料庫可使用下列命令，執行前先停止服務。

```powershell
.\NanoDesk-Server.exe -db "D:\NanoDesk\nanodesk.db" -backup "D:\Backup\nanodesk-backup.db"
```

未指定 `-config` 的舊 CLI 旗標仍有原本的設定入口，部署新端點池請使用已確認的設定檔。`GET /health` 可確認 HTTPS 服務是否回應，成功時傳回 `ok`。

## 8. 疑難排解

| 現象 | 檢查方式 |
| --- | --- |
| 遷移後無法直接啟動 | 確認端點池草案並儲存，解除待確認狀態。 |
| 憑證與名稱不符 | 一般連線位址、App 網址與憑證名稱需相符。 |
| Port 占用或無法監聽 | Port 是否被其他程式使用，綁定 IP 是否存在於本機。 |
| 本機可連，其他電腦不能連 | 是否使用 `127.0.0.1`、公布位址是否可達、入站埠與 NAT 轉送是否正確。 |
| 只有部分 App 能連 | 來源 CIDR 是否把它們分到不可達的端點組，網域是否解析到預期位址。 |
| 顯示容量不足 | 總容量、組容量、每端預留及現有預留數，並確認是否仍有排空中的連線。 |
| 立即停用後斷線 | 是否有可用替代端點，以及 HTTPS 協調連線是否仍在線。 |
| 設定頁看不到 UDP 埠 | 在右側內容區向下捲動，查看端點組下方欄位。 |
| App 無法上線 | App／伺服器版本一致、HTTPS 位址與 CA 正確，檢查服務紀錄。 |

協調層上限為 4,096 在線裝置、128 工作階段、每裝置 16 工作階段，每工作階段最長 24 小時。每個來源每分鐘最多三十次裝置註冊，短時間大量重連可能需要等待。

## 9. 目前驗證狀態

本機已驗證二十組共用單 Port 的混合工作階段、UDP／HTTPS TLS、混合路徑、IPv4／IPv6 跨端點、容量限制、熱套用失敗復原及路徑改派。1、2、5 Port 的本機量測、完整測試結果及既有 GDI 擷取失敗記錄見 [TESTING.md](../TESTING.md)。

你提供的截圖可確認主要設定頁面與欄位有顯示。實際儲存、服務啟動與遠端可達性仍需依部署位址確認；雙機、實體多網卡與跨 NAT 驗收依目前決定暫緩。執行檔大小與 SHA256 見 [BUILD-SIZES.txt](../BUILD-SIZES.txt)。
