# NanoDesk ID／中繼伺服器

單一 `NanoDesk-Server.exe` 整合 ID 登錄、線上狀態、TLS 協調、STUN／TURN UDP 及 TURN TLS；伺服器不需 Media Foundation 或螢幕。

## 視窗操作（不需要 CLI）

直接雙擊 `NanoDesk-Server.exe`，會開啟原生 Windows 視窗，不會跳出命令提示字元。第一次開啟自動進入設定；之後可點右上角「⚙ 設定」，在程式內開啟單一設定分頁。

1. **一般連線**：IPv4 與網域／DDNS 至少填一項，也可以兩欄都填。網域只填主機名稱，例如 `desk.example.com`。
2. **憑證與 ID 資料**：用「選擇檔案」選取 TLS 憑證／私鑰與 ID 資料庫位置。沒有憑證時可按「建立自簽憑證」，程式會建立新檔並填入路徑，不覆寫既有憑證。
3. **進階連接埠**：可直接修改監聽 IP、HTTPS、TURN、中繼範圍與頻寬。一般使用可保留預設值。
4. 按 **儲存並啟動**。主控台會顯示服務狀態、可複製的 APP 連線網址、在線裝置／工作階段／中繼數量及紀錄。
5. 在兩端 APP 的伺服器設定貼上主控台網址，登入同一台 ID 伺服器。

服務執行期間設定會鎖定；先按「停止服務」才能修改。停止或關閉程式會結束連線並釋放連接埠，可以重新啟動。設定分頁未儲存就關閉時會詢問儲存／捨棄／取消；切換分頁不影響服務。

可勾選「開啟程式時自動啟動服務」，讓下次雙擊程式時直接使用已儲存的設定。這不是 Windows 開機服務或開機自動執行。

設定存於 `%LOCALAPPDATA%\NanoDesk-Server\server-settings.json`，內容是設定值與檔案路徑，不含憑證私鑰內容。新資料庫預設也位於同一資料夾；若 EXE 旁已有舊版 `nanodesk.db`，第一次設定會優先沿用它，以保留既有 ID。設定檔中的相對路徑以設定檔資料夾為準。

### 使用自簽憑證

建立自簽憑證會產生伺服器憑證、伺服器私鑰及公開 CA 檔。伺服器憑證有效一年；CA 簽章私鑰不保存。

按 **匯出 CA 憑證**，將公開 CA 檔帶到兩端 APP 電腦，再在各 APP 的額外 CA 欄位指定該電腦上的檔案路徑。僅複製伺服器的本機路徑到其他電腦無法取代檔案傳送。匯出只接受公開憑證，拒絕私鑰。

使用既有公開受信任憑證時，可以不設定額外 CA。重建自簽憑證會產生新的 CA，APP 也需改用新 CA；程式不會停用憑證或主機名稱驗證。

### 網路設定

只填網域時，伺服器在每次啟動時解析 IPv4（DNS A 記錄）供 TURN 中繼使用。DDNS 指向新 IPv4 後，重新啟動服務即可重新解析，APP 繼續使用相同網域。兩欄都填時，APP 網址和 TLS 驗證使用網域，TURN 中繼使用手填的 IPv4。

若從外網連線且伺服器在 NAT 後方，須把下列埠轉送至該主機。

| 功能 | 預設 | 參數 |
| --- | --- | --- |
| HTTPS 協調 | TCP 443 | `-listen :443` |
| STUN／TURN | UDP 3478 | `-turn-port 3478` |
| TURN TLS | TCP 5349 | `-turn-tls-port 5349` |
| 中繼配置 | UDP 49160–49260 | `-relay-min`、`-relay-max` |
| 每配置雙向頻寬上限 | 20 Mbit/s | `-relay-mbps` |

開放上述入站埠並允許回程流量。TLS 客戶端使用 TCP，伺服器仍需開放中繼 UDP 範圍；雙方僅有 TCP 出站時，可各用 TLS 連到中繼。

`/signal` 需直接連至本服務；首版不讀取代理提供的來源 IP 標頭，不支援會改寫來源 IP 的反向代理。

`GET /health` 回傳 `ok`。記錄上／下線、工作階段與錯誤，不記錄密碼、桌面、剪貼簿或檔案內容。視窗會顯示有界的即時紀錄。停止服務請使用主控台按鈕；首版未提供 Windows 服務安裝器。

## 容量與授權

上限為 4,096 在線裝置、128 協調工作階段、每裝置 16 工作階段、256 中繼配置，實際數量也受 UDP 埠範圍限制。註冊、請求與訊息均有限流。工作階段最長 24 小時，屆時需重新建立。

中繼憑證綁定工作階段、裝置與來源 IP；刪除工作階段後，每個中繼封包都會重新檢查有效性。只允許相關對端公網 IP 或本伺服器中繼 IP，拒絕任意內網目的地及 TCP 目的地配置。

首版信任配置的協調伺服器。裝置經 TLS 進行金鑰挑戰驗證，SDP／DTLS 指紋由已驗證工作階段轉送；桌面授權由被控端判斷，TURN 不解碼桌面資料。

## ID 備份與還原

在主控台按 **備份 ID 資料庫** 並選擇目的地即可備份，服務執行中或停止後都能使用。執行中使用 bbolt 的一致快照，不需中斷連線；目的地不能覆蓋正在使用的資料庫。

ID／公鑰對應保存於資料庫，不回收離線 ID。遺失資料庫會失去原 ID 對應；EXE、設定、憑證與資料庫需分開備份。

還原時先停止服務，保留目前資料庫備份，再將快照複製至設定的 ID 資料庫路徑；或在設定分頁選取快照作為資料庫。重新啟動後，以同一 APP 身分確認 ID 相同。首版單節點，不含多節點同步或高可用部署。

## 選用 CLI 相容模式

日常操作不需要命令列。舊參數仍可用於腳本；帶參數啟動會使用 CLI 模式，沿用命令列設定，不讀取 GUI 設定檔：

```powershell
.\NanoDesk-Server.exe -cli -public-ip 203.0.113.10 -turn-host desk.example.com -cert server.crt -key server.key -db nanodesk.db
.\NanoDesk-Server.exe -db nanodesk.db -backup nanodesk-backup.db
```

範例位址需替換成實際資料；CLI 備份需先停止服務。GUI 已有對應按鈕，可直接使用。
